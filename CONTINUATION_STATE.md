## 1. WHAT THIS PROJECT IS

A full-stack educational web app with two interactive, mathematically-real simulations
(not screenshots): an **Op-Amp Differentiator** and an **Op-Amp Integrator**. Users
sign up / log in, land on a dashboard, pick an experiment, adjust R, C, amplitude,
frequency and waveform shape (sine/square/triangle) with sliders, and see live
input/output graphs, a circuit diagram, calculated values (RC time constant, corner
frequency, output peak), and educational text. Users can optionally save a run to
their history.

**Mandatory architecture (already implemented on the backend side):**
`Flutter Web  →  Node.js/Express REST API  →  MySQL/MariaDB`
Flutter never talks to MySQL directly. No MySQL credentials ever reach the frontend.

**Explicit non-goals (per original project owner's instructions — do not add these):**
Microservices, Kubernetes, complex state-management frameworks (Redux/Bloc etc. — we
use plain `provider` + `setState`), complicated auth (no OAuth/2FA), unrelated AI
features, unnecessary cloud infra, SPICE-level circuit simulation.

## 6. BACKEND API CONTRACT (already implemented & live-tested — treat as final)

Base path in code: `/api`. All bodies are JSON. Auth uses
`Authorization: Bearer <jwt>`. JWT payload is `{ id, email }`, secret from
`JWT_SECRET` env var, expiry from `JWT_EXPIRES_IN` (default `7d`).

**IMPORTANT ASYMMETRY (verified in the actual code, not a typo):** request bodies use
**camelCase** field names; the `experiment_sessions` API **responses** use
**snake_case** field names (they come straight from raw MySQL column names, unmapped).
The Flutter model's `toRequestJson()` and `fromJson()` must reflect this difference
exactly (see §7.3, `models/experiment_session.dart`).

| Method | Path | Auth | Body (camelCase) | Success | Notes |
|---|---|---|---|---|---|
| GET | `/api/health` | No | – | `200 { status:'ok', service:'opamp-lab-backend' }` | liveness check |
| POST | `/api/auth/signup` | No | `{ name, email, password }` (password ≥ 6 chars) | `201 { token, user:{id,name,email} }` | `409` if email exists, `400 { message, errors[] }` on validation failure |
| POST | `/api/auth/login` | No | `{ email, password }` | `200 { token, user:{id,name,email} }` | `401 { message:'Invalid email or password.' }` |
| GET | `/api/auth/profile` | Yes | – | `200 { user:{id,name,email,created_at} }` | `401` if missing/expired/invalid token |
| POST | `/api/experiments` | Yes | `{ experimentType, waveformType, resistanceOhm, capacitanceF, amplitudeV, frequencyHz, notes? }` (all numeric fields must be > 0; `experimentType` ∈ {differentiator,integrator}; `waveformType` ∈ {sine,square,triangle}) | `201 { session:{ id, experiment_type, waveform_type, resistance_ohm, capacitance_f, amplitude_v, frequency_hz, notes, created_at } }` | `400` on validation failure |
| GET | `/api/experiments` | Yes | – | `200 { sessions:[ {...same shape as above...}, ... ] }` | newest first, capped at 50 |
| DELETE | `/api/experiments/:id` | Yes | – | `204` (empty body) | `404` if not found / not owned by caller, `400` if `:id` isn't a positive integer |

CORS: in `NODE_ENV !== 'production'` any origin is allowed (so `flutter run -d chrome`
works out of the box on its random dev port). In production, set `CORS_ORIGIN` in
`.env` to the deployed frontend's exact origin.

Error shape convention: `{ message: string, errors?: string[] }`. Raw DB/driver errors
are **never** leaked (`middleware/errorHandler.js` catches `ER_DUP_ENTRY`,
`ECONNREFUSED`, etc. and returns clean messages; anything else becomes a generic
`500 { message: 'Something went wrong...' }`).

### 7.4 Simulation logic (the mathematical core — get this exactly right)

**`lib/logic/waveform_generator.dart`**
```dart
enum WaveformType { sine, square, triangle }
// WaveformType.sine.name == 'sine' etc. — matches backend waveformType strings directly, use .name when calling the API.

class WaveformGenerator {
  static double valueAt({required WaveformType type, required double amplitude,
      required double frequencyHz, required double timeSeconds}) {
    final period = 1 / frequencyHz;
    double phase = (timeSeconds % period) / period; // 0..1
    switch (type) {
      case WaveformType.sine:
        return amplitude * math.sin(2 * math.pi * frequencyHz * timeSeconds);
      case WaveformType.square:
        return phase < 0.5 ? amplitude : -amplitude;
      case WaveformType.triangle:
        if (phase < 0.25) return 4 * amplitude * phase;
        if (phase < 0.75) return 2 * amplitude - 4 * amplitude * phase;
        return -4 * amplitude + 4 * amplitude * phase;
    }
  }

  // 3 full cycles, 240 samples/cycle -> 721 points total. Chosen so waveforms look
  // smooth and finite-difference/trapezoidal math below is numerically well-behaved.
  static List<double> generateTimeAxis({required double frequencyHz,
      int cycles = 3, int pointsPerCycle = 240}) {
    final period = 1 / frequencyHz;
    final totalPoints = cycles * pointsPerCycle;
    final dt = (period * cycles) / totalPoints;
    return List<double>.generate(totalPoints + 1, (i) => i * dt);
  }
}
```
*(The triangle formula is deliberately phase-aligned with the sine wave — it starts at
0, peaks at `+A` a quarter-period in, crosses 0 at half-period, troughs at `-A` at
three-quarters — so that differentiating a triangle visibly produces a square wave and
the three waveform types are visually comparable on the same time axis.)*

**`lib/logic/simulation_result.dart`**
```dart
// Models a real op-amp's output swing on a typical ±15V supply (~1.5V headroom lost
// to saturation near the rails). Clamping to this value is what keeps the ideal
// differentiator's edge "spikes" (which are infinite in the pure math for a square
// wave) finite and pedagogically honest — mention this in the UI, not hidden.
const double kOpAmpSaturationVoltage = 13.5;

class SimulationResult {
  final List<double> time;   // seconds
  final List<double> vin;    // volts
  final List<double> vout;   // volts, already clamped to ±kOpAmpSaturationVoltage
  final double rcSeconds;
  final double cornerFrequencyHz; // 1 / (2*pi*R*C)
  final double outputPeakV;       // max(|vout|)
  const SimulationResult({ ...required all fields... });
  bool get isSaturating => outputPeakV >= kOpAmpSaturationVoltage - 0.05;
}
```

**`lib/logic/differentiator_simulator.dart`** — ideal relation `Vout = -RC·dVin/dt`,
implemented as a backward finite difference:
```dart
class DifferentiatorSimulator {
  static SimulationResult run({required WaveformType waveform, required double amplitudeV,
      required double frequencyHz, required double resistanceOhm, required double capacitanceF}) {
    final time = WaveformGenerator.generateTimeAxis(frequencyHz: frequencyHz);
    final vin = time.map((t) => WaveformGenerator.valueAt(
        type: waveform, amplitude: amplitudeV, frequencyHz: frequencyHz, timeSeconds: t)).toList();
    final rc = resistanceOhm * capacitanceF;
    final n = time.length;
    final vout = List<double>.filled(n, 0);
    for (int i = 1; i < n; i++) {
      final dt = time[i] - time[i - 1];
      vout[i] = -rc * (vin[i] - vin[i - 1]) / dt;
    }
    vout[0] = n > 1 ? vout[1] : 0;
    for (int i = 0; i < n; i++) {
      vout[i] = vout[i].clamp(-kOpAmpSaturationVoltage, kOpAmpSaturationVoltage);
    }
    final peak = vout.fold<double>(0, (p, v) => math.max(p, v.abs()));
    return SimulationResult(time: time, vin: vin, vout: vout, rcSeconds: rc,
      cornerFrequencyHz: 1 / (2 * math.pi * rc), outputPeakV: peak);
  }
}
```

**`lib/logic/integrator_simulator.dart`** — ideal relation `Vout = -(1/RC)·∫Vin dt`,
implemented as cumulative trapezoidal integration:
```dart
class IntegratorSimulator {
  static SimulationResult run({required WaveformType waveform, required double amplitudeV,
      required double frequencyHz, required double resistanceOhm, required double capacitanceF}) {
    final time = WaveformGenerator.generateTimeAxis(frequencyHz: frequencyHz);
    final vin = time.map((t) => WaveformGenerator.valueAt(
        type: waveform, amplitude: amplitudeV, frequencyHz: frequencyHz, timeSeconds: t)).toList();
    final rc = resistanceOhm * capacitanceF;
    final n = time.length;
    final vout = List<double>.filled(n, 0);
    double integral = 0;
    for (int i = 1; i < n; i++) {
      final dt = time[i] - time[i - 1];
      integral += (vin[i] + vin[i - 1]) / 2 * dt;   // trapezoidal rule
      vout[i] = -(1 / rc) * integral;
    }
    for (int i = 0; i < n; i++) {
      vout[i] = vout[i].clamp(-kOpAmpSaturationVoltage, kOpAmpSaturationVoltage);
    }
    final peak = vout.fold<double>(0, (p, v) => math.max(p, v.abs()));
    return SimulationResult(time: time, vin: vin, vout: vout, rcSeconds: rc,
      cornerFrequencyHz: 1 / (2 * math.pi * rc), outputPeakV: peak);
  }
}
```

**Sanity-check numbers (already worked out — use to verify your implementation):**
At the default params (R=10 kΩ, C=100 nF ⇒ RC = 1 ms, fc ≈ 159.15 Hz, A=5V, f=100Hz,
sine wave): differentiator peak ≈ `RC·A·ω = 0.001×5×(2π×100) ≈ 3.14 V`; integrator peak
≈ `A/(RC·ω) = 5/(0.001×2π×100) ≈ 7.96 V`. Both comfortably under the 13.5V clamp — a
good non-saturating default demo. If your numbers come out very different, re-check
sign/units before proceeding.

### 7.5 Services (talk to the backend — never talk to MySQL)

**`lib/services/api_client.dart`**
- `class ApiException implements Exception { final String message; final int? statusCode; ... }`
- `class ApiClient` with `baseUrl` defaulting to `kApiBaseUrl`, and methods
  `Future<Map<String,dynamic>> get(String path, {String? token})`,
  `post(String path, Map<String,dynamic> body, {String? token})`,
  `delete(String path, {String? token})`.
- Each method: builds headers (`Content-Type: application/json`, plus
  `Authorization: Bearer $token` if a token is passed), calls `package:http`,
  wraps in `try/catch` for `TimeoutException` (use `.timeout(const Duration(seconds: 10))`)
  and generic network failures, and turns them into a friendly `ApiException`
  ("Could not reach the server. Is the backend running?").
- On response: if `res.body` isn't empty, `jsonDecode` it. If `statusCode` is in
  200–299 return the decoded map; otherwise throw `ApiException` using the server's
  `message` field when present, else a generic "Request failed (`<code>`)." This is
  what makes the "backend unavailable" / "invalid values" / "duplicate email" error
  states in the UI possible — every screen should catch `ApiException` and show
  `e.message` to the user (never show a raw stack trace or DB error).

**`lib/services/auth_service.dart`**
- Wraps `ApiClient` for `/auth/signup`, `/auth/login`, `/auth/profile`.
- Persists the JWT in `shared_preferences` under a single key (e.g.
  `'opamp_lab_token'`) via `getSavedToken()`, `_saveToken()`, `clearToken()`.
- `signup(...)`/`login(...)` save the token on success and return a `User`.
- `fetchProfile(String token)` calls `GET /auth/profile` and returns a `User`
  (used on app startup to silently restore a session from a saved token).

**`lib/services/auth_provider.dart`** (`ChangeNotifier`, registered once at the app
root with `provider`) — holds `User? user`, `String? token`, `bool isLoading`,
`String? error`, `bool initialized` (false until startup auto-login check finishes).
Exposes `bool get isAuthenticated => user != null && token != null;`.
- `Future<void> tryAutoLogin()`: read saved token; if none, just set
  `initialized = true`. If present, try `fetchProfile`; on success populate
  `user`/`token`; on failure (expired/invalid), call `clearToken()` silently. Always
  end with `initialized = true; notifyListeners();`. Called once from `main.dart`.
- `Future<bool> signup(...)`/`login(...)`: set `isLoading = true`, clear `error`,
  call the service, populate `user`/`token` on success (return `true`), or set
  `error = e.message` on `ApiException` (return `false`); always
  `isLoading = false; notifyListeners();` in a `finally`.
- `Future<void> logout()`: clear `user`/`token`, call `AuthService().clearToken()`,
  `notifyListeners()`.

**`lib/services/experiment_service.dart`**
- `Future<ExperimentSession> saveSession({required String token, required ExperimentSession session})`
  → `POST /experiments` with `session.toRequestJson()`, parse `data['session']`.
- `Future<List<ExperimentSession>> listSessions(String token)` → `GET /experiments`,
  map `data['sessions']` (a `List`) through `ExperimentSession.fromJson`.
- `Future<void> deleteSession(String token, int id)` → `DELETE /experiments/$id`.

### 7.6 Widgets

**`lib/widgets/waveform_chart.dart`** — takes a `SimulationResult result` and renders
**two** stacked `fl_chart` `LineChart`s (not one combined chart — the original spec
explicitly asks for separate Vin-vs-t and Vout-vs-t graphs, and independent
auto-scaled y-axes read much better here since Vout can be clamped to a very different
range than Vin, e.g. spikes near ±13.5V for a differentiated square wave):
- Chart 1: title "Input Voltage (Vin) vs Time", one `LineChartBarData` from
  `result.time`/`result.vin` as `FlSpot`s, blue.
- Chart 2: title "Output Voltage (Vout) vs Time", one `LineChartBarData` from
  `result.time`/`result.vout`, red/orange (use orange if `result.isSaturating` to
  visually flag clipping).
- Both need: `gridData: FlGridData(show: true)`, bottom axis titled "Time (s)" with
  tick labels (`toStringAsFixed(3)` or similar — time values are small, e.g. 0–0.03s
  at 100Hz/3cycles), left axis titled "Voltage (V)", `borderData` outline,
  `dotData: FlDotData(show: false)` (too many points to show dots), `isCurved: false`
  (the raw sampled shape, especially spikes/edges, must not be smoothed away).
- If the installed `fl_chart` version's `AxisTitles`/`SideTitles` API differs from
  what you expect, adapt to it — the *requirement* (readable axes with units, a grid,
  and both curves updating when parameters change) is what matters, not the exact
  fl_chart class names.

**`lib/widgets/circuit_diagrams.dart`** — two widgets,
`DifferentiatorCircuitDiagram` and `IntegratorCircuitDiagram` (or one
`CircuitDiagram({required bool isDifferentiator})`), each wrapping a `CustomPaint`
with a `CustomPainter` that draws, with plain `Canvas`/`Path`/`Paint`/`TextPainter`
primitives (**no external asset/image files** — draw everything in code to avoid any
copyright concern about tracing a third-party site's graphics):
- An op-amp as a triangle (two input wires on the flat side labelled `−` and `+`, one
  output wire from the apex).
- For the **differentiator**: input node → **capacitor** symbol (two short parallel
  plates) → inverting (`−`) input; feedback **resistor** (zigzag) from output back to
  the inverting input node; non-inverting (`+`) input wired straight to a ground
  symbol; output node on the right.
- For the **integrator**: input node → **resistor** (zigzag) → inverting input;
  feedback **capacitor** (parallel plates) from output back to the inverting input;
  `+` input grounded; output node on the right.
- Label every node: `Vin`, `Vout`, `R`, `C`, `GND`, `−`, `+`.
- Helper methods worth writing once and reusing: `_drawResistorZigzag(canvas, p1, p2, paint)`,
  `_drawCapacitorPlates(canvas, midpoint, paint)`, `_drawGroundSymbol(canvas, point, paint)`,
  `_drawOpAmpTriangle(canvas, rect, paint)`, `_drawLabel(canvas, text, offset, style)`.
- This does **not** need to be a physically simulated SPICE-accurate drawing — it just
  needs to clearly communicate the real circuit topology, per the original spec.

**`lib/widgets/control_panel.dart`** — takes `SimulationParams params`,
`ValueChanged<SimulationParams> onChanged`, `VoidCallback onRunPressed`,
`VoidCallback onSavePressed`, `bool isSaving`, `String? saveMessage`. Renders:
- A `Slider` each for R (1,000–100,000, label shows current Ω), C (1–1,000, label
  shows current nF), Amplitude (0.5–10, label shows current V), Frequency (10–2,000,
  label shows current Hz) — each `onChanged` calls `onChanged(params.copyWith(...))`
  immediately (**live update**, satisfies "the output must actually change when input
  parameters change" — don't gate this behind only the button).
- A waveform selector — three `ChoiceChip`s ("Sine", "Square", "Triangle") in a `Wrap`,
  selected state driven by `params.waveform`.
- A prominent `ElevatedButton` labelled **"RUN / UPDATE SIMULATION"** calling
  `onRunPressed` (kept per the original spec even though sliders already live-update —
  gives users an explicit, satisfying "do the thing" action and is a good place to,
  e.g., show a brief SnackBar confirmation).
- A secondary button **"Save This Run"** calling `onSavePressed`, disabled/showing a
  small spinner while `isSaving`, and showing `saveMessage` below it when non-null
  (success or error text — the message itself already distinguishes the two cases,
  see `experiment_screen.dart` below).

**`lib/widgets/results_summary.dart`** — takes a `SimulationResult result` and the
current `SimulationParams`, and renders a small card/table of:
- τ = RC (auto-scaled to ms/µs as appropriate, e.g. "1.00 ms"), clearly labelled as
  **calculated**.
- Corner frequency `fc = 1/(2πRC)` — also calculated — with a one-line explanatory
  note comparing it to the user's chosen frequency (e.g. "Your input frequency is
  ~0.63× the corner frequency").
- User-set inputs echoed back (R, C, amplitude, frequency, waveform) clearly labelled
  as **user input**, distinct visually/textually from the calculated values above.
- Computed output peak voltage.
- If `result.isSaturating`, a visible warning: something like "⚠ Output has reached
  the simulated op-amp's supply-rail limit (±13.5 V) and is clipping. Try reducing R,
  C, or amplitude." — and a permanent small-print note: "This is an idealized
  educational simulation based on ideal op-amp equations, not a physically perfect
  circuit."

**`lib/widgets/info_section.dart`** — takes an `ExperimentConfig config`, renders a
`Card` with: title, the `formula` in a large monospace-ish styled `Text`, the
`principle` paragraph, and `keyPoints` as a bulleted list (`Column` of `Row(children:[Icon(Icons.circle, size: 6), Expanded(child: Text(point))])` or similar). Keep it
concise — the original spec explicitly says not to over-fill with textbook paragraphs.

### 7.8 App shell

**`lib/app.dart`**
```dart
class OpAmpLabApp extends StatelessWidget {
  const OpAmpLabApp({super.key});
  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Op-Amp Virtual Lab',
      debugShowCheckedModeBanner: false,
      theme: buildAppTheme(),
      home: const AuthGate(),
    );
  }
}

class AuthGate extends StatelessWidget {
  const AuthGate({super.key});
  @override
  Widget build(BuildContext context) {
    final auth = context.watch<AuthProvider>();
    if (!auth.initialized) {
      return const Scaffold(body: Center(child: CircularProgressIndicator()));
    }
    return auth.isAuthenticated ? const DashboardScreen() : const LoginScreen();
  }
}
```
This reactive-swap pattern is why login/signup/logout need **no manual navigation
logic** beyond pushing between Login↔Signup — `AuthGate` handles the rest, and it's
also why "logout" must live only on `DashboardScreen` (the screen `AuthGate` itself
shows), not on a screen pushed on top of it, to avoid leaving stale routes on the
Navigator stack (see §7.7).

**`lib/main.dart`**
```dart
void main() {
  runApp(
    ChangeNotifierProvider(
      create: (_) => AuthProvider()..tryAutoLogin(),
      child: const OpAmpLabApp(),
    ),
  );
}
```
